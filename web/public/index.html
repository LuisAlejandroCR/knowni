Registro

Tres ficheros, y nada más

Este dominio no tiene producto. Existe para que dos máquinas puedan comprobar algo: un verificador, quién firma; un teléfono, que la passkey es de esta app.

Raíz de confianza /registry.json

El documento de registro firmado. Su digest está anclado en cadena: las dos raíces de confianza son sobre estos mismos bytes, nunca sobre dos documentos.

Pendiente /.well-known/apple-app-site-association

iOS valida este dominio contra el team id y el bundle antes de dejar usar una passkey.

Pendiente /.well-known/assetlinks.json

Lo mismo en Android, contra la huella del certificado con el que se firma el build.

Los tres se generan desde el repositorio. El documento se firma fuera de este servidor: la semilla de la autoridad no vive donde vive el sitio.
